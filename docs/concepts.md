# 核心概念

模型每一轮看到的东西就三份：**系统提示词**、**工具目录**、**技能目录**。随着插件与 MCP 越装越多，这三份只会越来越大，拖累模型表现；而 DSH 目前给子代理的配置又极其简陋。

本插件把「某个 Agent 到底看到什么」变成一组可配置的对象。理解下面几个词，就理解了全部。

## 四个池

四类配置对象各管各的，可以多对多引用：集建好之后，能被多个代理装载。

| 池 | 干什么用 |
| --- | --- |
| **代理** Agents | 指定绑给哪个预设；配 Agent 模式（传统 / PTC）、提示词、工具、skill、子代理名册，以及被当子代理时的模型与思考强度 |
| **提示词集** promptSets | 有序的提示词清单，顺序可调 |
| **工具集** toolSets | 工具名清单，插件的和 MCP 的都在里面 |
| **技能集** skillSets | Skill 清单，决定哪些能被 AI 自主调用 |

## 装载与绑定

两个动作，分工不同：

- **装载**：把集挂到代理上。同一个代理装载的集之间不允许有重叠成员，界面和写入端点各拦一道。
- **绑定**：把某个预设绑到一个代理上，这个预设就交给它管了。

## 语义边界：没装就是空的

绑定之后，三面一个规矩：**没装就是空的**。

| 概念 | 规则 |
| --- | --- |
| 绑定预设 | 被绑定的预设，提示词、工具、skill、子代理全部交给这个代理；解除绑定即恢复原样 |
| 提示词集 | 一个都不装 = 投递空提示词 |
| 工具集 | 一个都不装 = 一个工具都不给 |
| 技能集 | 一个都不装 = 一个 skill 都不暴露；装了就只看勾的 |

没绑主代理的预设完全不受影响，随插随用。

## 预设、代理与子代理

- **预设**是 DSH 自己的对象，管提示词组合与技能注册。
- 本插件不动预设文件，只在**装配期**接管：预设被绑定后，这一轮实际投递什么由代理的配置决定。
- **子代理**（被主代理派活的后台代理）也能用自己的一套：模型走启动参数、工具面在创建窗口收窄、提示词与技能面在装配期生效。

## 什么时候生效

插件工作在**装配期**：每次对话开始时，平台把「这一轮要投递什么」组装成装配结果，插件在这一步按你的配置改写它。由此有两条实用推论：

- 改完配置要**点保存**，然后**新开一个对话**生效；
- 卸载插件，装配回到平台原样——因为宿主文件从头到尾没被改过。
